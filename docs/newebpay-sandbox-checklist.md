# NewebPay Sandbox Checklist

Use this after the payment routes are deployed to a public HTTPS origin.

## Dashboard URLs

- Notify URL: `https://app.pacergo.app/api/payments/newebpay/notify`
- Return URL: `https://app.pacergo.app/api/payments/newebpay/return`

`ClientBackURL` is generated by the app as `https://app.pacergo.app/payments/newebpay/result`.

## Before Testing

- Rotate the exposed HashKey and HashIV in the NewebPay dashboard.
- Store the new values only in local/deployment environment variables.
- Set `NEWEBPAY_ENV=sandbox`.
- Deploy the callback routes to a publicly reachable HTTPS environment.
- Configure the Notify URL and Return URL in NewebPay after deployment.

## Manual Scenarios

- Open a payable booking as the seeker.
- Confirm the review amount matches the booking price.
- Start payment and reach the NewebPay sandbox checkout.
- Try each enabled sandbox method shown by NewebPay, such as WebATM, ATM, convenience-store code, and barcode if available.
- Complete a successful payment.
- Complete or simulate a failed payment.
- Abandon or cancel a payment.
- Confirm ReturnURL redirects to `/payments/newebpay/result` without raw provider fields.
- Confirm NotifyURL updates the payment and booking status.
- Refresh the result page.
- Open the result page in another authenticated tab.
- Attempt to access the result as another user.
- Replay a duplicate valid callback fixture.
- Attempt an altered amount or merchant order number fixture.
- Retry only after a failed or expired attempt.
- Verify asynchronous instructions and expiration behavior where NewebPay returns them.

Localhost cannot receive NewebPay server callbacks. A tunnel is optional for development, but not required when the deployed app is public.
